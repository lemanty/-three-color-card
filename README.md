# 三色牌

使用 Unity 制作的卡牌构筑肉鸽游戏。通过排列计分牌、融合颜色和商店运营，构筑能够击败最终 Boss 的牌组。

## 打开项目

1. 安装 Unity Editor **6000.0.42f1**（工程原版本）。
2. 在 Unity Hub 中添加本仓库根目录，即包含 `Assets`、`Packages`、`ProjectSettings` 的目录。
3. 等待 Unity 导入资源，然后打开 `Assets/Scenes/SampleScene.unity`。

首次打开时 Unity 会重新生成 Library 等缓存。仓库保留资源及其 `.meta` 文件、包依赖和项目设置，不提交生成的缓存或 IDE 工程文件。

## 当前进度

已实现单场战斗原型：初始十五张牌、主要阶段选三张、三个次要阶段结算、计分区排序、替换两张牌、弃牌洗牌、资源累加和胜负判定。进入现有场景并点击 Play 后，会自动生成原型界面。商店、融合操作、地图和 Boss 流程尚未实现。

操作方式：先点击手牌选择指定数量，替换阶段还需点选两张计分牌；点击“放入计分区”，用左右箭头排列，最后确认。最右侧为主牌。主要阶段确认不计分，后三个阶段各结算一次。

次要阶段二、三：点击计分牌下方的“移出”标记两张旧牌（可点“取消移出”撤销），选择两张手牌后点击“替换两张牌”。替换完成后仍可点击“返回重选”，恢复本阶段原有手牌和计分牌；只有“确认排列 · 结算”后才结束该阶段。

原型暂定每种颜色各有 1～5 点的五张牌，目标分数 60，金币和分数保留小数。同色倍率同时作用于本次资源收益；同色和全异色按完整颜色组合判定，全异色的永久加点在本次结算后生效。这些尚未确认的细则和数值可以在后续试玩中调整。当前没有融合入口，但结算模型支持复合颜色。

规则验证：在 PowerShell 中运行 `./Tests/Test-BattleRules.ps1`，覆盖 1000 场完整流程、卡牌守恒、非法选择、排列、洗牌、三次累计结算及混色资源收益。

2026 年 10 月 18 日验证：上述规则检查通过，全部游戏脚本使用本机 Unity 自带 Roslyn 编译器和现有工程依赖编译通过。Unity 编辑器启动因缺少有效许可证而退出，尚未完成 Play 模式交互和视觉验证；需要先在 Unity Hub 登录并激活许可证。

主要文件：

- `Assets/Scripts/Card/Card.cs`：卡牌显示逻辑。
- `Assets/Scripts/Card/CardData.cs`：卡牌数据定义。
- `Assets/Scripts/Core/GameManager.cs`：原型界面和交互。
- `Assets/Scripts/Core/BattleState.cs`：独立于 Unity 的战斗规则与运行时卡牌状态。
- `Assets/Prefabs/CardPrefab.prefab`：卡牌预制体。
- `Assets/Scenes/SampleScene.unity`：现有场景。

## 已确认的设计

2026 年 10 月 18 日确认：

- 每场战斗结算三次：主要阶段放入三张牌，不结算；次要阶段一补齐五张后结算，随后两个次要阶段各结算一次。
- 抽牌堆耗尽后，将弃牌堆洗混继续抽牌。
- 融合牌兼具其颜色的效果，例如红蓝主牌同时提高分数并获得能量。
- 当前版本以击败最终 Boss 为通关条件。

完整构想和历史记录保存在根目录的 `新卡牌肉鸽游戏的构想.docx`、`开发日志.docx`、`项目文件说明.docx`。文档包含旧版本设想，冲突处以最新确认的设计为准。
